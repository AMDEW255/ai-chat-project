Все примеры лежат в папках рядом с этим файлом: example1_freeze, example2_timer, example3_promise, example4_fetch, example5_async_await. Это обычные index.html + script.js — никакого интернета, всё работает у тебя на компьютере. Как открывать — по шагам в первой плашке «Практика».

1. JavaScript делает одно дело за раз

Код выполняется сверху вниз, строчка за строчкой. Пока не закончилась одна строка — следующая не начнётся. Это называется синхронный код.

console.log('раз');
console.log('два');
console.log('три');
// в консоли: раз, два, три — всегда в этом порядке

Проблема: некоторые вещи занимают время. Например, запрос к нейросети идёт через интернет и может думать 2–5 секунд. Если бы JavaScript просто «стоял и ждал» ответа — на это время зависла бы вся страница: кнопки не нажимаются, текст не печатается, ничего.

Аналогия
Ты заказала пиццу по телефону. Ты же не стоишь у двери 40 минут, не двигаясь, пока её везут. Ты вешаешь трубку и занимаешься своими делами, а когда пицца приедет — курьер позвонит в дверь. Вот это и есть асинхронность: «начни долгое дело, а меня позови, когда будет готово».

2. Самый простой асинхронный код — таймер

setTimeout(функция, время) говорит: «подожди столько-то миллисекунд, потом выполни эту функцию». 1000 миллисекунд = 1 секунда.

console.log('до таймера');

setTimeout(function () {
    console.log('прошло 2 секунды!');
}, 2000);

console.log('после таймера');

В каком порядке появятся строки в консоли?

до таймера — сразу
после таймера — тоже сразу, не дожидаясь таймера
прошло 2 секунды! — через 2 секунды

Вот это неожиданно для новичков. setTimeout не останавливает код. Он как будто говорит: «поставил будильник, иду дальше». JavaScript досматривает все оставшиеся строки, и только когда ему станет нечего делать — берётся за отложенную функцию.

Отложенные функции складываются в очередь задач (task queue). JavaScript заглядывает в неё только после того, как доделал весь основной код. Поэтому даже setTimeout(fn, 0) — с нулевой задержкой — не выполнит fn прямо сейчас: она всё равно встанет в конец очереди и подождёт своей очереди.

Смотри, что мы сделали: передали в setTimeout целую функцию как аргумент. Не результат её работы, а саму функцию — чтобы setTimeout вызвал её сам, позже.

Ты уже так делала и раньше, просто не задумывалась. Вспомни конец своего chat.js:

document.querySelector('.send-btn').addEventListener('click', sendMessage);

Здесь sendMessage написано без скобок (). Ты не вызываешь функцию — ты отдаёшь её браузеру, а он вызовет её сам, когда пользователь кликнет по кнопке. С setTimeout то же самое: отдаёшь функцию, а вызовут её через заданное время.

Родственник — setInterval

То же самое, но повторяет функцию каждые N миллисекунд, пока не остановишь через clearInterval. Пригодится, если захочешь, например, мигающий индикатор «Печатает…».

3. Промис (Promise) — «обещание, что ответ будет»

Когда дело долгое, JavaScript не может вернуть результат сразу — его же ещё нет. Вместо результата он возвращает промис: специальный объект-расписку, «я обещаю, что здесь появится результат… потом».

У промиса три состояния:

СостояниеЧто значит
pending (ожидание)дело ещё идёт, результата нет
fulfilled (выполнен)всё получилось, результат готов
rejected (отклонён)дело сорвалось (например, пропал интернет и запрос вообще не дошёл)

Промис начинается в pending и потом один раз переходит либо в fulfilled, либо в rejected. Обратно уже не вернётся.

Как забрать результат из промиса

  • .then(результат => { ... }) — «когда получится, сделай вот это с результатом»
  • .catch(ошибка => { ... }) — «если сломается, сделай вот это»
какойТоПромис
    .then(function (результат) {
        console.log('готово:', результат);
    })
    .catch(function (ошибка) {
        console.log('облом:', ошибка);
    });
Про стрелочку =>
Дальше в коде часто встретится запись вида response => response.json(). Это просто короткий способ написать функцию: x => y — то же самое, что function (x) { return y }. В .then и .catch можно писать как захочешь — обе записи работают одинаково.
Аналогия
Промис — это талончик из гардероба. Пальто тебе сразу не отдают, но талончик (обещание) — на руках. .then — это «когда позовут по номеру, забери пальто». .catch — «если пальто потеряли, вот что делать».

4. Теперь читаем твой fetch по строчкам

Вот кусок из твоего chat.js. Раньше он был непонятной магией — сейчас пройдём по нему.

loaderIndicator.classList.remove('hidden')   // 1. показали надпись "ИИ печатает..."

fetch("https://api.deepseek.com/chat/completions", {   // 2. отправили запрос
    method: "POST",
    headers: {
        "Content-Type": "application/json",
        "Authorization": "Bearer " + API_KEY
    },
    body: JSON.stringify({
        model: "deepseek-v4-flash",
        messages: [ { role: "user", content: userText } ]
    })
})
    .then(response => response.json())   // 3. пришёл ответ — превращаем в объект
    .then(data => {                       // 4. теперь работаем с данными
        loaderIndicator.classList.add('hidden')       // спрятали надпись
        const reply = data.choices[0].message.content;
        // ...добавляем сообщение ИИ на страницу...
    });
  1. Показали надпись «ИИ печатает…». В твоём проекте это <p class="loader hidden">ИИ печатает...</p>. Мы знаем, что дальше будет ожидание, поэтому заранее снимаем с неё класс hidden, чтобы пользователь видел — ответ грузится.
  2. fetch(...) отправляет запрос и сразу возвращает промис (состояние pending). Ответа от нейросети ещё нет! Код не ждёт — он идёт дальше, страница остаётся живой.
  3. Первый .then. Когда сервер ответил, промис становится fulfilled, и мы получаем response — «сырой» ответ. Чтобы достать из него JSON, вызываем response.json(). Важно: .json() — это тоже долгая операция, она тоже возвращает промис. Поэтому нужен ещё один .then.
  4. Второй .then. Вот здесь у нас наконец готовый объект data. Прячем надпись «ИИ печатает…», достаём текст ответа data.choices[0].message.content и выводим на страницу.
Почему два .then подряд
Первый распаковывает ответ сети в JSON (тоже промис), второй — работает с уже готовыми данными. Каждый .then «ждёт», пока предыдущий закончится, и передаёт результат дальше по цепочке.

Чего в твоём коде не хватает — .catch

Сейчас что-то может пойти не так двумя способами:

  • Пропал интернет — запрос вообще не дошёл, промис от fetch становится rejected.
  • Сервер ответил, но не тем, чего мы ждём (ошибка ключа, лимит запросов). Тогда fetch считает, что всё хорошо — ответ же пришёл! — но в data не будет поля choices, и строчка data.choices[0].message.content упадёт с ошибкой.

В обоих случаях без обработки надпись «ИИ печатает…» останется висеть навсегда, а в консоли будет красная ошибка. .catch в конце цепочки ловит и то, и другое — добавь его:

    .catch(error => {
        loaderIndicator.classList.add('hidden');
        messagesBox.innerHTML += '<p class="msg msg-ai">Ошибка, попробуй ещё раз</p>';
        console.log(error);
    });

5. Современная запись — async / await

Цепочки .then().then().then() тяжело читать. В новом JavaScript есть способ написать асинхронный код так, будто он обычный, сверху вниз.

  • Перед функцией пишем слово async — «внутри будет ожидание».
  • Перед промисом пишем await — «подожди тут результат, потом иди дальше». Строчка ниже не выполнится, пока не придёт ответ — но страница при этом не зависает.
async function sendMessage() {
    // ...показали надпись "ИИ печатает..."...

    try {
        const response = await fetch("https://api.deepseek.com/chat/completions", {
            method: "POST",
            headers: {
                "Content-Type": "application/json",
                "Authorization": "Bearer " + API_KEY
            },
            body: JSON.stringify({
                model: "deepseek-v4-flash",
                messages: [ { role: "user", content: userText } ]
            })
        });

        const data = await response.json();   // ждём распаковку

        loaderIndicator.classList.add('hidden');
        const reply = data.choices[0].message.content;
        // ...выводим ответ на страницу...
    } catch (error) {
        loaderIndicator.classList.add('hidden');
        console.log('Ошибка:', error);
    }
}

Это тот же самый код, что с .then — просто читается как обычный рассказ: «отправь запрос → дождись ответа → дождись распаковки → покажи». try/catch здесь играет роль .catch.

Запомни
await работает только внутри функции, помеченной async. «Ждёт» он по-умному: пауза только для этой функции, а браузер в это время спокойно реагирует на клики и прокрутку.

Бонус — finally

Заметь: строчку «спрятать надпись» пришлось написать дважды — и в try, и в catch. Чтобы не дублировать, есть третий блок — finally. Он выполняется в любом случае: и когда всё получилось, и когда была ошибка.

    try {
        const response = await fetch(...);
        const data = await response.json();
        // ...показать ответ...
    } catch (error) {
        // ...показать ошибку...
    } finally {
        loaderIndicator.classList.add('hidden');   // спрячется всегда
    }
