Основные команды Git — просто и по делу

Короткий справочник по командам, которые нужны в начале пути: сохранить изменения, посмотреть историю, поработать с ветками и загрузить проект на GitHub. Под каждой командой — что она делает и живой пример.

1 git init

Превращаем папку в репозиторий — Git начинает следить за изменениями.

2 git add .

Отмечаем файлы, которые хотим сохранить в следующем снимке.

3 git commit -m "..."

Делаем снимок отмеченных файлов с описанием, что изменилось.

4 git remote add origin <ссылка>

Один раз связываем папку с репозиторием на GitHub, куда будем всё отправлять.

5 git push -u origin main

Отправляем снимки на GitHub, чтобы их видели остальные.

Шаг 4 нужен только один раз для проекта — если репозиторий уже подключён, сразу переходите к git push. Без него git push выдаст ошибку «no configured push destination».

Настройка

Выполняется один раз на компьютере или один раз в новом проекте.

git init

Создаёт в текущей папке скрытую папку .git — с этого момента Git запоминает историю изменений этой папки.

$ git init Initialized empty Git repository in ./ai-chat-project/.git/
git config

Говорит Git, как подписывать снимки — от чьего имени они сделаны. Настраивается один раз на весь компьютер.

$ git config --global user.name "Маша" $ git config --global user.email "masha@example.com"
git clone <ссылка>

Скачивает существующий репозиторий с GitHub к себе на компьютер вместе со всей историей.

$ git clone https://github.com/имя/проект.git
.gitignore

Не команда, а обычный текстовый файл в корне проекта. В нём построчно перечисляют файлы и папки, которые Git должен игнорировать — не показывать в git status и не предлагать в git add. Обычно туда попадают файлы, которые не нужны в истории: пароли и ключи (.env), папка с установленными пакетами (node_modules), временные и системные файлы.

.gitignore ──────────── node_modules/ .env *.log

Важно: правило работает только для файлов, которые Git ещё не отслеживает. Если файл уже был закоммичен раньше, добавление его в .gitignore не остановит слежку — сначала нужно снять его с учёта командой git rm --cached <файл>.

Ежедневный цикл

Эти три команды используются каждый раз, когда нужно сохранить прогресс.

git status

Показывает, какие файлы изменились и что из них уже готово к сохранению. Самая безопасная команда — ничего не меняет, только показывает.

$ git status modified: chat.js untracked: notes.md
git add <файл>

Отмечает файл как готовый к сохранению. git add . отмечает сразу все изменённые файлы в папке.

$ git add chat.js $ git add .
git commit -m "сообщение"

Сохраняет снимок отмеченных файлов навсегда в историю. Сообщение в кавычках коротко объясняет, что изменилось — это как подпись под фотографией.

$ git commit -m "добавила время к сообщениям"

История

Смотрим, что уже было сохранено, и что именно изменилось.

git log

Показывает список всех сохранённых снимков (коммитов) — кто, когда и с каким сообщением их сделал. Полезно добавить --oneline, чтобы список был короче.

$ git log --oneline 1f8bedb docs: add lesson 11 d899d2a docs: add lesson 10 22d5445 feat: store chat messages
git diff

Показывает построчно, что именно изменилось в файлах с прошлого сохранения — какие строки удалили, а какие добавили.

$ git diff chat.js - console.log("старое") + console.log("новое")

Ветки

Ветка — это отдельная линия работы, чтобы пробовать новое, не трогая основной код.

git branch

Без аргументов — показывает список веток и отмечает, в какой из них вы сейчас находитесь. С именем — создаёт новую ветку.

$ git branch * main new-feature
git switch <ветка>

Переключает на другую ветку. Чтобы сразу создать ветку и перейти в неё — git switch -c <имя>.

$ git switch -c new-feature
git merge <ветка>

Забирает изменения из указанной ветки в ту, где вы сейчас находитесь. Обычно так соединяют готовую фичу с основной веткой main.

$ git switch main $ git merge new-feature

Работа с GitHub

Синхронизация локального репозитория с копией на GitHub.

git remote add origin <ссылка>

Связывает локальный репозиторий с адресом на GitHub — под коротким именем origin. Делается один раз для проекта.

$ git remote add origin https://github.com/имя/проект.git
git push

Отправляет сохранённые коммиты из компьютера на GitHub. Первый раз обычно пишут git push -u origin main, дальше достаточно просто git push.

$ git push -u origin main
git pull

Забирает свежие изменения с GitHub на компьютер — например, если проект менялся с другого устройства.

$ git pull origin main

Отмена изменений

Команды на случай ошибок. Часть из них меняет историю — используйте аккуратно и по очереди, не все сразу.

git restore <файл>

Отменяет несохранённые изменения в файле, возвращая его к последнему коммиту. Полезно, если что-то сломали и хотите начать заново.

$ git restore chat.js
⚠ осторожно
git reset

Отменяет последние коммиты, как будто их не было. Хорошо подходит для своих ещё не отправленных на GitHub изменений — но не после git push, если кто-то ещё пользуется репозиторием.

$ git reset --soft HEAD~1
git revert <коммит>

Безопасный способ отменить старый коммит: создаёт новый коммит, который откатывает изменения, а историю не переписывает. Годится даже после git push.

$ git revert 22d5445

Словарик на всякий случай

Репозиторий
Папка проекта, за которой следит Git — со всей сохранённой историей изменений.
Коммит
Один сохранённый снимок файлов с подписью, что в нём изменилось.
Ветка (branch)
Отдельная линия разработки — можно пробовать идеи, не трогая основной код.
origin
Короткое имя для адреса репозитория на GitHub, с которым синхронизируется компьютер.

Практика: соберите репозиторий с нуля

Пройдите шаги по порядку в терминале — это тот же путь, что и на схемах выше, только руками. Понадобится папка на компьютере и аккаунт на GitHub.

1

Создайте папку проекта

Создайте где угодно на компьютере новую папку practice-git — обычным способом, через проводник или VS Code — и откройте её в терминале VS Code (меню Terminal → New Terminal). Какой именно это терминал — не важно: команды git работают одинаково и в PowerShell (он открывается по умолчанию), и в Git Bash, и в обычном cmd.

$ cd practice-git

cd — команда терминала (не Git), она переводит вас в указанную папку, чтобы дальше все команды выполнялись именно в ней.

2

Инициализируйте репозиторий

$ git init

Теперь в папке появилась скрытая .git — Git начал следить за изменениями.

3

Создайте файл и посмотрите на него глазами Git

Создайте в этой папке файл about.txt любым удобным способом — например, через VS Code (правой кнопкой → New File) или проводник — и напишите в нём любую строку текста. Это обычное действие с файлом, Git тут ни при чём.

$ git status Untracked files: about.txt

Файл появился на диске, но Git пока его не отслеживает — отсюда и untracked («неотслеживаемый»).

4

Сделайте первый коммит

$ git add about.txt $ git commit -m "первый коммит"

Файл попал в индекс, а потом — снимком в историю локального репозитория.

5

Создайте пустой репозиторий на GitHub и подключите его

На github.com нажмите New repository, назовите его practice-git, не добавляйте README — иначе истории на GitHub и локально разойдутся.

$ git remote add origin https://github.com/ваш-логин/practice-git.git $ git push -u origin main

Первый push с флагом -u запоминает связку — дальше достаточно просто git push.

6

Измените файл и отправьте новую версию

Допишите в about.txt ещё одну строку и сохраните файл.

$ git diff $ git add about.txt $ git commit -m "добавила вторую строку" $ git push

git diff перед добавлением — привычка, которая показывает, что именно вы сохраняете.

7

Попробуйте ветку

$ git switch -c experiment

Допишите в about.txt ещё одну строку и сохраните.

$ git add about.txt $ git commit -m "пробное изменение"

Коммит попал только в ветку experiment — в main его пока нет.

8

Слейте ветку обратно и отправьте на GitHub

$ git switch main $ git merge experiment $ git push

Теперь изменения из experiment — часть main, и они отправлены в GitHub.

9

Посмотрите на всю историю

$ git log --oneline

Список коммитов, которые вы только что сделали руками — от первого до слияния ветки.
