Урок 14

TypeScript — типы поверх твоего JavaScript

Дальше на курсе будет React, а почти весь React-код в реальных проектах пишут на TypeScript. Это два быстрых урока, чтобы прочитать чужой TS-код и писать свой на базовом уровне — без глубокого погружения, ровно чтобы не спотыкаться в React.

Как устроен урок

В этот раз практика начинается не с готовых файлов — ты сама создашь проект командой в терминале, как это делают в реальной работе. Дальше внутри своего проекта будешь создавать файлы с примерами по инструкции: что скопировать, куда вставить, что дописать самой.

Урок идёт кусочками теории, и после каждого — оранжевая плашка 🔧 Практика. Лучше разбирать пример сразу, пока теория перед глазами.

0. Создаём проект

TypeScript — это не отдельный язык программирования «с нуля», а JavaScript плюс типы. Ты пишешь почти тот же код, что и раньше, но дополнительно указываешь, какого «сорта» значение хранится в переменной, что принимает и что возвращает функция. Файлы называются не .js, а .ts.

Браузер TypeScript не понимает — он всегда выполняет обычный JavaScript. Поэтому нужен инструмент, который заранее проверит типы и превратит .ts в .js. В этом уроке — Vite: он же понадобится и в React, так что заодно познакомишься с ним заранее.

🔧 Практика — создание проекта
  1. Открой терминал в VS Code (меню Terminal → New Terminal) и перейди в корень своего проекта (папка ai-chat-project-fresh, где лежат chat.js, lesson12_async и т.д.).
  2. Выполни команду: 
    npm create vite@latest lesson14_typescript -- --template vanilla-ts
    Она создаст новую папку lesson14_typescript рядом с lesson12_async, с заготовкой TypeScript-проекта внутри.
  3. Перейди в неё и поставь зависимости: 
    cd lesson14_typescript
npm install
  4. Запусти локальный сервер: 
    npm run dev
    В терминале появится адрес вида http://localhost:5173/ — открой его в браузере. Сервер остаётся работать, пока не нажмёшь Ctrl+C в терминале — не закрывай эту вкладку терминала весь урок.
  5. Ты увидишь дефолтную страницу Vite со счётчиком — это просто шаблон-заглушка, шаг 5 её уберёт.
Важно
Vite не проверяет типы во время работы сервера — он только быстро собирает файлы, чтобы страница обновлялась мгновенно. Ошибки типов ты будешь видеть в редакторе (красное подчёркивание в VS Code) и по команде npx tsc --noEmit в терминале — она молча проверяет весь проект на ошибки типов, ничего не собирая.

1. Зачем нужны типы

В обычном JavaScript переменная может в любой момент стать чем угодно:

let age = 25;
age = 'двадцать шесть'; // JS не против, ошибки не будет

Это работает, пока код маленький. Но если age потом используют в математике (age + 1) — программа не упадёт сразу, а тихо сломается где-то дальше, и искать причину придётся уже после того, как это увидел пользователь.

TypeScript даёт способ сказать заранее: «эта переменная — всегда число», и если кто-то (в том числе ты сама через месяц) попробует положить туда строку — TypeScript укажет на ошибку сразу в редакторе, до запуска.

let age: number = 25;
age = 'двадцать шесть'; // ошибка типа — увидишь сразу
Аналогия
Обычный JS — склад без подписанных коробок: класть можно что угодно куда угодно, а потом кладовщик долго ищет, куда делись гвозди, если кто-то положил туда яблоки. TypeScript — те же коробки, но с подписями. Положить не то — тебе сразу скажут на входе, а не когда коробку откроют на другом конце склада.
🔧 Практика — пример 1: первая пойманная ошибка
src/examples/example1_first_error.ts
  1. Создай в src/examples/ файл example1_first_error.ts с содержимым: 
    // ПРИМЕР 1 — зачем нужен TypeScript
export function run() {
    let age: number = 25;
    console.log('возраст:', age);

    age = 26;
    console.log('возраст после дня рождения:', age);
}
  2. Открой src/main.ts и замени содержимое на: 
    import { run } from './examples/example1_first_error'

run()
  3. Сохрани, открой консоль в браузере — увидишь два console.log. Ошибок нет: 26 — тоже число, всё по правилам.
  4. Теперь сломай нарочно: замени строку age = 26; на age = 'двадцать шесть';. Посмотри на редактор — под этой строкой появится красная волнистая линия. Наведи курсор — увидишь текст ошибки.
  5. В терминале (в новой вкладке терминала, не останавливая npm run dev) выполни: 
    npx tsc --noEmit
    Увидишь ту же ошибку текстом: Type 'string' is not assignable to type 'number'.
  6. Верни age = 26; обратно и убедись, что ошибка пропала.

2. Базовые типы

Самые частые типы в TypeScript — те же понятия, что и в JS, только теперь их можно назвать явно после двоеточия:

ТипЧто хранитПример
stringтекстlet name: string = 'Аня'
numberлюбое числоlet age: number = 20
booleantrue / falselet isOnline: boolean = true
string[]массив строкlet tags: string[] = ['js', 'ts']
number[]массив чиселlet scores: number[] = [10, 20]

Часто тип можно вообще не писать — TypeScript сам его угадывает по значению справа (это называется вывод типа, type inference):

let city = 'Киев'; // TypeScript сам понял: это string

Явно писать тип полезно там, где значения ещё нет — например, у параметров функции (увидишь в разделе 4).

Тип any — и почему его лучше избегать
Есть тип any — «может быть чем угодно», он выключает всю проверку для этой переменной. Иногда он реально нужен (например, работа со старым JS-кодом без типов), но если ставить any везде «чтобы TypeScript не ругался» — смысла в TypeScript не остаётся вообще. Используй его только когда правда не можешь описать тип иначе.

3. Типизация объектов через interface

Объекты — это то, с чем ты работаешь постоянно (вспомни createMessage в своём chat.js, который возвращает объект с полями text, time, sender). В TypeScript можно заранее описать, какие поля обязаны быть у объекта и какого они типа — через interface:

interface User {
    name: string;
    age: number;
}

const user: User = {
    name: 'Аня',
    age: 20
};

Если в объекте не хватает поля, лишнее поле, или тип поля не совпал — TypeScript укажет на ошибку сразу при создании объекта, а не когда где-то в коде обратятся к несуществующему полю.

Необязательные поля — знак ?

Если поле есть не у всех объектов этого вида, ставь после его имени ?:

interface User {
    name: string;
    age: number;
    isAdmin?: boolean; // может отсутствовать
}

const user1: User = { name: 'Аня', age: 20 };            // ок, isAdmin не указан
const user2: User = { name: 'Игорь', age: 30, isAdmin: true }; // тоже ок
interface или type?
Ты ещё можешь встретить похожую запись через type: type User = { name: string; age: number }. Для описания формы объекта они почти всегда взаимозаменяемы — на этом уровне разницу можно не запоминать, увидишь оба варианта в чужом коде. В React пропсы компонентов описывают именно так — этот приём пригодится уже на следующем уроке.

4. Типизация функций

У функции можно указать тип каждого параметра и тип того, что она возвращает — после стрелки не нужно, тип результата пишется после скобок с параметрами:

function sum(a: number, b: number): number {
    return a + b;
}

Если внутри случайно вернуть не то (например, строку вместо числа) — TypeScript укажет на ошибку прямо в функции, а не там, где результат потом используют.

Необязательные и значения по умолчанию

function greet(name: string, greeting: string = 'Привет'): string {
    return `${greeting}, ${name}!`;
}

greet('Аня');              // 'Привет, Аня!'
greet('Аня', 'Здравствуй'); // 'Здравствуй, Аня!'

Параметр со значением по умолчанию можно не передавать — TypeScript сам понимает, что он необязательный.

🔧 Практика — пример 4
src/examples/example4_functions.ts
  1. Создай файл: 
    // ПРИМЕР 4 — типизация функций

    function sum(a: number, b: number): number {

    console.log('сумма:', sum(2, 3));

        return `${greeting}, ${name}!`;
    }

    console.log(greet('Аня'));
    console.log(greet('Аня', 'Здравствуй'));

    // ДОПИШИ ЗДЕСЬ:
    // напиши функцию multiply(a: number, b: number): number,
    // которая возвращает произведение, и вызови её
}
  2. Поменяй импорт в main.ts, сохрани, проверь консоль.
  3. Допиши multiply.
  4. Сломай нарочно: в sum замени return a + b; на return 'готово';. Посмотри на ошибку у слова return — TypeScript не даст вернуть не тот тип, который обещан после скобок. Верни как было.

5. Union-типы — значение из нескольких вариантов

Иногда переменная может быть не любой строкой, а только одной из нескольких заранее известных — например, статус запроса. Такие варианты перечисляют через | (палка, «или»):

type Status = 'loading' | 'success' | 'error';

function showStatus(status: Status): string {
    if (status === 'loading') return 'Загрузка...';
    if (status === 'success') return 'Готово!';
    return 'Ошибка загрузки';
}

Если попробовать передать в showStatus что-то, кроме этих трёх строк — например, 'pending' — TypeScript сразу укажет на ошибку. Это ровно то, что происходит у тебя в чате с состоянием загрузки (loaderIndicator либо показан, либо скрыт) — только здесь TypeScript не даст опечататься в названии статуса.

🔧 Практика — пример 5
src/examples/example5_union_types.ts
  1. Создай файл: 
    // ПРИМЕР 5 — union-типы (значение из нескольких вариантов)

    }

    console.log(showStatus('loading'));
    console.log(showStatus('success'));
    console.log(showStatus('error'));

    // ДОПИШИ ЗДЕСЬ:
    // объяви свой union-тип Theme = 'light' | 'dark'
    // и переменную theme: Theme с любым из двух значений
}
  2. Поменяй импорт в main.ts, сохрани, проверь консоль.
  3. Допиши Theme и theme.
  4. Сломай нарочно: вызови showStatus('pending'). Посмотри на ошибку — такого варианта нет среди разрешённых. Убери эту строку обратно.
